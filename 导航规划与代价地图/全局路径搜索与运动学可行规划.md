# 全局路径搜索与运动学可行规划

全局规划器在给定地图和起终点后，寻找一条空间路径。它解决的是“从哪里经过”，不自动解决速度如何随时间变化、执行器能否跟踪，也不保证定位误差下的安全。路径表示的状态、地图代价和动作模型决定了“最优”究竟是什么意思。

本文从图搜索讲到 Nav2 的网格与运动学规划器。曲率跟踪、速度限制与局部避障见[局部轨迹控制与速度约束](局部轨迹控制与速度约束.md)；占据空间如何变成 costmap 见[分层代价地图与障碍生命周期](分层代价地图与障碍生命周期.md)。

## 1. 把地图变成图

搜索问题可写为加权图 $G=(V,E)$：节点 $v\in V$ 是候选位置或位姿，边 $(u,v)\in E$ 表示允许的一步动作，边权 $c(u,v)$ 表达距离、风险或时间。障碍格应从可通行节点中排除，软代价格则进入边权。

例如一种简单的栅格边权是：

$$
c(u,v)=\ell(u,v)\left(1+\lambda\frac{C(v)}{C_{max}}\right),
$$

其中 $\ell$ 是一步的几何长度，$C(v)$ 是非致命代价，$\lambda\ge0$ 控制风险偏好。该式只是说明“距离与代价共同影响路径”的模型；实际规划器的代价积分、障碍阈值和未知格规则各有定义。若格代价被误当作概率，代价大小就失去含义。

四邻接栅格只允许上下左右移动，曼哈顿距离

$$h_4=r(|\Delta i|+|\Delta j|)$$

是几何下界；八邻接允许斜向移动时，常用 octile 距离

$$h_8=r\left[\max(|\Delta i|,|\Delta j|)+(\sqrt2-1)\min(|\Delta i|,|\Delta j|)\right].$$

如果允许斜穿两个相邻障碍格的夹角，中心点之间虽相邻，具有尺寸的机器人仍可能撞到角落。邻接关系必须与碰撞检查和地图分辨率一致。

## 2. Dijkstra 与 A*

Dijkstra 逐次扩展当前累计代价 $g(n)$ 最小的节点。对每条边尝试松弛：

$$
g(v)\leftarrow\min\{g(v),\ g(u)+c(u,v)\}.
$$

只要边权非负，且实现正确，Dijkstra 就能找到图上最小累计代价路径。它可能需要扩展起点附近大量与目标无关的节点。

A* 在累计代价上加剩余代价估计：

$$
f(n)=g(n)+h(n).
$$

若启发函数 $h(n)$ 从不高估节点到目标的真实最小剩余代价（可采纳），A* 可在相应图搜索条件下找到最优解，同时通常比 Dijkstra 更快聚焦目标方向。若 $h$ 一致，已扩展节点无需重新打开；若 $h$ 可采纳但不一致，实现必须允许改进后的节点重新进入 open set，否则图搜索可能漏掉最优解。启发函数过高估会放弃最优保证；地图使用软代价时，几何距离仍可作下界，但要确认单位与最低每米代价。

### 一个可运行的四邻接 A* 示例

以下程序用 `None` 表示硬障碍，用 0–252 的数字表示软代价。启发函数采用曼哈顿距离；进入格子的边权由长度 1 和软代价组成。程序只负责示例图，不处理未知格、footprint、TF 或地图更新。

```python
from heapq import heappop, heappush
from math import isfinite

GRID = [
    [0, 0, 0, 0, 0, 0, 0, 0],
    [0, None, None, None, 0, 100, 100, 0],
    [0, 0, 0, None, 0, 100, 100, 0],
    [0, None, 0, None, 0, 100, 100, 0],
    [0, None, 0, 0, 0, 0, 0, 0],
    [0, 0, 0, None, None, None, 0, 0],
]
START, GOAL = (0, 0), (5, 7)
RISK_WEIGHT = 0.8


def astar(grid, start, goal, risk_weight):
    if not grid or not grid[0]:
        raise ValueError("grid must be non-empty")
    if not isinstance(risk_weight, (int, float)) or not isfinite(risk_weight) or risk_weight < 0:
        raise ValueError("risk_weight must be finite and non-negative")
    rows, cols = len(grid), len(grid[0])
    if any(len(row) != cols for row in grid):
        raise ValueError("grid must be rectangular")
    if any(value is not None and
           (not isinstance(value, (int, float)) or not isfinite(value)
            or not 0 <= value <= 252)
           for row in grid for value in row):
        raise ValueError("cell costs must be in [0, 252] or None")

    for cell in (start, goal):
        if (not isinstance(cell, tuple) or len(cell) != 2
                or any(not isinstance(index, int) for index in cell)):
            raise ValueError("start and goal must be integer (row, col) tuples")

    def inside(cell):
        row, col = cell
        return 0 <= row < rows and 0 <= col < cols

    if not inside(start) or not inside(goal):
        raise ValueError("start and goal must lie inside the grid")
    if grid[start[0]][start[1]] is None or grid[goal[0]][goal[1]] is None:
        raise ValueError("start and goal must not be blocked")
    if start == goal:
        return [start], 0.0

    def heuristic(cell):
        return abs(cell[0] - goal[0]) + abs(cell[1] - goal[1])

    frontier = [(heuristic(start), 0.0, start)]
    best = {start: 0.0}
    parent = {}

    while frontier:
        _, cost, current = heappop(frontier)
        if cost != best[current]:
            continue  # 丢弃优先队列中已经过时的条目
        if current == goal:
            path = [goal]
            while path[-1] != start:
                path.append(parent[path[-1]])
            return list(reversed(path)), cost

        row, col = current
        neighbors = ((row - 1, col), (row + 1, col),
                     (row, col - 1), (row, col + 1))
        for neighbor in neighbors:
            if not inside(neighbor):
                continue
            cell_cost = grid[neighbor[0]][neighbor[1]]
            if cell_cost is None:
                continue
            next_cost = cost + 1.0 + risk_weight * cell_cost / 252.0
            if next_cost >= best.get(neighbor, float("inf")):
                continue
            best[neighbor] = next_cost
            parent[neighbor] = current
            priority = next_cost + heuristic(neighbor)
            heappush(frontier, (priority, next_cost, neighbor))

    raise ValueError("no path exists")


if __name__ == "__main__":
    path, total_cost = astar(GRID, START, GOAL, RISK_WEIGHT)
    print("path:", " -> ".join(map(str, path)))
    print(f"cost: {total_cost:.3f}")
```

此例采用四邻接图、每步至少代价 1 的非负边权与曼哈顿启发。该启发函数不仅可采纳，而且一致；因此这段实现可以在节点出队时结束目标搜索。优先队列保留过时条目并按最新 `best` 丢弃，也允许一个已扩展节点在后来得到更低代价时重新进入队列。

示例中低代价通道让路径沿最上方绕行；若改变软代价权重或障碍布局，最优路线会变。真实导航还要考虑格中心离散误差、机器人的尺寸、未知区、路径平滑和执行模型。

## 3. Nav2 网格规划器

Nav2 的插件把不同搜索假设封装成可替换的 planner。插件 ID 是配置名，算法类型由 ID 下的 `plugin` 指定；一次规划请求还可以选择具体 ID，不能只看 YAML 里注册了什么。

### NavFn

NavFn 在二维代价地图上进行势场式扩展并提取路径，可选择 Dijkstra 或 A* 展开。它将机器人近似成平面上的圆形/点状模型，因此路径方向和最小转弯半径不是搜索状态。适合运动学要求较弱或允许原地转向的底盘。`use_astar`、未知区策略、目标容差等参数的解释应以所用发行版的 Nav2 文档为准。

### Smac 2D、Hybrid-A* 与 State Lattice

Smac 是 A* 系列规划器：

- **Smac 2D** 搜索栅格位置 $(i,j)$，可将 costmap 软代价纳入路径代价，适合可近似为圆形或平面全向模型的机器人。
- **Smac Hybrid-A*** 搜索平面位姿 $(x,y,\theta)$，用离散格和朝向桶管理节点，同时以连续位姿和运动原语扩展。它可采用 Dubins（仅前进）或 Reeds–Shepp（允许倒车）曲线族作为运动模型，并可用解析连接尝试快速接近目标。
- **Smac State Lattice** 使用预先生成的控制原语表达可行运动，适合需要更灵活运动学约束的底盘。

简化自行车模型为：

$$
\dot{x}=v\cos\theta,\qquad
\dot{y}=v\sin\theta,\qquad
\dot{\theta}=v\kappa,\qquad
|\kappa|\le \frac{1}{R_{min}}.
$$

运动原语必须符合模型，代价地图碰撞检查还必须采用实际 footprint。Hybrid-A* 不等于“任意转弯的差速车控制”；差速车可原地旋转，而 Dubins 模型要求正的最小转弯半径。搜索完成后做路径平滑，也必须重新检查平滑轨迹是否仍在安全区域内。

### Theta*

Theta* 在 A* 网格搜索中加入父节点到新邻点的视线检查。若这条较长线段无碰撞，且代价更小，可把新点的父节点设为当前节点的父节点：

$$
g(v)=g(\operatorname{parent}(u))+c(\operatorname{parent}(u),v).
$$

这样路径可跨过多个格中心，减少网格方向导致的锯齿。但中心点连线无碰撞不代表带尺寸机器人无碰撞；视线检查须遍历线段经过的格子并考虑软代价或安全距离。Theta* 也不处理速度、加速度和运动学可行性。

## 4. 硬安全域与软代价

设 $D(x)$ 为位置到阻塞源的距离，要求安全距离为 $r_s$，可把搜索域限制为：

$$
\mathcal S=\{x:D(x)\ge r_s\}.
$$

这是硬约束；膨胀层生成的软代价则只是鼓励路径远离障碍。两者可以组合，但要避免重复加大安全余量。圆形 $r_s$ 容易实现，却可能无法覆盖偏置矩形车体的所有朝向；机器人 footprint、起终点容差和允许未知区都要与控制器碰撞规则协调。

## 5. 点到点路径与区域覆盖

点到点规划只要求连接起点和目标；覆盖路径规划还要求机器人工作区域尽可能完整地扫过。对近似矩形的自由区域，可将工作面分解成平行条带，生成往返式（lawnmower）路线；障碍和凹形边界较多时，先按障碍切分可行区域，再分别覆盖各个连通片，避免简单地在边界内来回穿越。

不论采用条带、回字或其他路线，执行时都应记录已经被工具 footprint 覆盖的区域，而不只是机器人中心经过的格子。遇到障碍、掉头空间不足或任务中断时，应从仍未覆盖的可达区域重新选段；只找到一个未访问栅格，还不能证明附近区域可由机器人安全到达。区域分解、转弯代价、重叠率和覆盖率需要结合工具宽度及边界误差定义。

## 6. 搜索规划的验证边界

“搜索返回一条路径”只说明它满足了规划器自己使用的图模型和碰撞检查。部署前还需逐项确认：

- 地图未知区是拒绝、允许，还是只按比例限制。
- 硬障碍与软代价分别怎样进入搜索边权。
- 八邻接或视线 shortcut 是否会切过障碍角点。
- 起终点是否允许吸附到附近安全格，吸附后是否改变任务语义。
- 路径方向、朝向、倒车段是否与 controller 匹配。
- 平滑或插值后是否重新验证完整 footprint 与障碍间距。
- 地图更新时，搜索所用代价图是否是同一时刻的一致快照。

全局搜索算法不负责控制误差、角度环绕、速度加速度限位和执行器接口；坐标变换见[坐标变换与传感器标定](../坐标变换与传感器标定/坐标系、刚体变换与TF.md)，轨迹和控制见[机器人运动学与控制](../机器人运动学与控制/README.md)。
