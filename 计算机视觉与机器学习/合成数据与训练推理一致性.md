# 合成数据与训练推理一致性

视觉模型管道由多个阶段组成：选择背景、合成目标、同步变换、写入缓存、加载张量、训练、导出，再在运行时重建同一个输入。阶段间若通道顺序、坐标、归一化或标签含义不同，模型即使成功运行也可能看到另一种任务。

## 一条可复现的样本管道

    来源索引 + 场景组 + 随机种子
        → 背景与标注
        → 合成目标、难例与增强
        → 图像 / 几何 / 红外 / 标签同步
        → 样本池与来源清单
        → 数据加载与训练
        → 权重 + 配置 + 统计量 + 导出模型

合成建池是 CPU 图像生成与写盘任务；训练是读取样本、前向与反向更新权重的任务。它们的瓶颈不同。评估数据生成吞吐、磁盘流量和模型训练耗时应分别记录；看到单一功耗读数无法判断是哪一阶段受限。完整的资源测量方法见[CUDA与性能分析](../CUDA与性能分析/性能测量、延迟与瓶颈分析.md)。

## 合成目标要与场景和标签一致

合成数据可控制目标位置、尺寸、方向、模糊和难例，使罕见组合更容易覆盖。每次合成都要保留来源背景、使用的随机种子、增强参数、标签版本和合成配方。标签应随几何变换精确移动，目标边缘和遮挡关系也要与输入图一致。

**多模态输入需要按物理含义处理。** 若一个样本同时含可见光、深度和红外：

- 翻转、旋转、裁剪或透视等几何变换应共享同一组参数，使同一物体在各通道仍对齐。
- 可见光、连续深度等信号可按其语义选择线性插值；类别标签、有效性掩码通常应使用最近邻。重采样后重新检查无效区和边界。
- 光度增强只应作用于其有物理依据的模态。改变 RGB 亮度不应顺手改写 IR 或深度；若合成线缆被画入 RGB，其他通道也应渲染匹配的观测，或显式标记该样本不提供该模态。
- 同一几何变换并不意味着同一种强度变换。传感器的响应、噪声与反射特征可能不同。
- 多路图像要按采集时间和已声明的同步规则配对。没有配到对应观测时，应显式标记该模态缺失，不要悄悄沿用上一帧。
- 来源中确实缺少模态，与某个模态观测值为零，是两件事。若用零填充表达缺失，应有独立的有效性标记，并确保训练时见过这种缺失模式。
- 没有测量支持的反射率、噪声或材料参数应明确标为合成假设，再用真实采集数据验证。合成目标的某个模态若无法可信渲染，要显式标缺失或排除样本，不要把整张通道置零后当作真实观测。

可把同步增强抽象为伪代码（接口示意，不可直接运行）：

    G = draw_geometric_transform(seed)
    image  = warp(image,  G, interpolation="bilinear")
    depth  = warp(depth,  G, interpolation="sensor-specific")
    label  = warp(label,  G, interpolation="nearest")
    valid  = warp(valid,  G, interpolation="nearest")

深度若含无效编码，应使用与传感器定义一致的插值和有效性更新策略。若 RGB 与深度原本不在同一图像坐标中，先完成几何配准；这部分由[坐标变换与传感器标定](../坐标变换与传感器标定/坐标系、刚体变换与TF.md)主讲。

## 固定随机过程与样本池

可复现合成数据需要的不只是一个全局 seed，还要明确每个样本和各类增强如何抽取随机数。可按样本 ID 派生独立随机流，例如背景选择、几何增强、颜色变化与模态缺失分开。新增一种增强时使用新增的随机流，避免消耗旧随机序列后让所有后续样本改变。

对固定输入索引、配方版本和 seed，重建应得到相同的样本和标签。manifest 至少应记录：

- 原始来源标识与数据划分组；
- 生成器代码和配置的版本或哈希；
- 随机种子及随机过程约定；
- 输入通道、单位、形状和归一化；
- 各模态是否存在、缺失原因与有效区域；
- 标签格式、忽略区语义和样本池分片校验值。

冻结的配方便于复现，也便于比较新配方。已有配方需要改变时，使用独立版本标识并保留旧行为，避免无声地改变缓存含义。对新旧版本做逐样本对等检查时，应固定来源、seed 和公共参数；除预期变化的字段外，前一版本字段、标签、有效掩码与重试序列都应一致。只比一张可视化图不足以排除随机流或缓存顺序改变。

## 模态缺失要作为训练条件

如果推理阶段可能缺少 RGB、深度或 IR，可以在训练中随机丢弃模态或使用真实缺失样本，但不能随意将不同情况混成同一零值。训练策略需要记录：

- 每种人为丢弃模式的概率；
- 源数据自然缺失的比例；
- 哪些组合被允许，是否保留至少一种有效模态；
- 缺失填充值与对应存在标记；
- 推理端缺失时的超时、回退或不输出语义。

随机丢模态分布是部署故障分布的假设，需要用开发数据覆盖预期模式。若训练时从未出现过 RGB 全零，而运行时却把缺彩色帧直接填零，网络的输出没有依据。每种约定都应做输入张量核对，并逐模式验证最终掩膜。

## 训练—导出—推理的数值一致性

对一个模型接口，先固定输入形状、通道语义、颜色顺序、张量布局、数据类型和归一化，再选静态或动态形状的导出方式。运行时应读取或核对模型输入签名；张量通道、维度或数据类型不匹配时要在前向计算前明确失败。模型有 BatchNorm 等运行统计量时，导出前应处于评估模式。

训练网络可能输出 logits，导出包装器则可能在图中附加 sigmoid，或后端在外部附加该变换。两种设计都可用，但必须选一种并确保恰好应用一次。重复 sigmoid 会改变概率；遗漏 sigmoid 则会把未界定范围的 logits 当成概率比较阈值。

数值核对分层进行：

1. **输入层**：在同一批原始帧上逐通道比较预处理张量，检查顺序、坐标、插值、有效掩码、缺失填充和数据类型。
2. **模型输出层**：以 PyTorch FP32 为参考，比较导出模型和目标运行时的最大、平均绝对误差及误差分布；同时检查 NaN、Inf 和边界像素。
3. **决策层**：比较阈值附近的像素、二值掩膜、连通区域与下游输出。微小概率误差可让接近阈值的像素翻转，因此只比较平均误差不足。
4. **系统层**：在实际设备与代表性负载下检查完整输入、推理、后处理和队列延迟。单独 kernel 时间不代表整条管线延迟，具体测量归入[CUDA与性能分析](../CUDA与性能分析/性能测量、延迟与瓶颈分析.md)。

ONNX checker 能发现模型图结构或格式不一致，但不能证明运行时输出与原模型数值一致。降低精度可能提高速度或节省内存，也会带来数值偏差；对 FP16 等模式应分别报告误差和实际任务指标。

诊断部署差异时，可保存关键阶段数组：模型原始输出、几何对齐后输出、阈值掩膜。这样能判断差异来自模型本身、插值/坐标变换、阈值还是后处理，而不必只比较最终一张图。

OpenCV DNN 可通过 cv::dnn::readNetFromONNX 加载 ONNX 图，并用 Net 执行前向计算。模型成功加载只说明当前导入器接受了图；仍需核对输入张量形状、通道布局、输出节点和概率变换，再与训练框架逐值比较。不同推理后端支持的算子和数值行为可能不同。
