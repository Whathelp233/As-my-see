# 学习计划与复盘

学习路径不必从一份固定课程表开始。先明确要解决的问题，再确认它依赖哪些概念和工具；用小练习检查基础，用一个范围可控的项目把几个知识点串起来，最后根据结果决定下一步。这个过程适用于自学，但阶段长度和顺序要按主题、基础和可用时间调整。

## 把目标写成可检查的结果

把“学会某主题”改写为能观察的产出，例如“能解释输入与输出”“能完成一个最小例子”“能用已知数据检查结果”。目标越明确，越容易判断还缺什么。

可以把目标拆成四层：

1. **概念**：说清术语、单位、前提和边界。
2. **小练习**：不依赖复杂环境地复现一个核心步骤。
3. **组合任务**：把两三个已学步骤连成一个小工具或一个小实验。
4. **验证**：准备输入、预期现象和失败条件，检查结果而不是只看代码能否运行。

## 排学习顺序

先列出完成目标必须理解的前置知识，再按依赖关系安排，而不要只按网上课程的章节顺序推进。用简短的前测找出当前缺口：一道手算题、一段小程序、一次文档阅读或一个测量都可以。尚未掌握的前置内容先补到足以开展目标任务的程度。

分阶段增加复杂度通常比一次引入许多新工具更容易定位问题：

- 先固定输入，单独确认一个概念或接口。
- 再改变一个条件，观察结果是否按预期变化。
- 最后组合多个组件，并记录各组件之间的输入、输出和假设。

例如，一条嵌入式学习建议把 C 语言和电路基础放在前面，再做裸机微控制器练习、学习 RTOS，并在任务需要时补 Linux。这里仅保留“先学前置基础、再逐步组合”的顺序示例，不代表唯一课程路线。这个顺序是规划办法，不是对所有学科都适用的固定课表。

## 用项目产生反馈

项目要足够小，能在有限时间内做完、解释和检查。开始前写下：

- 想回答的问题或完成的功能；
- 输入、输出及单位；
- 预期结果和允许误差；
- 哪些条件暂时固定；
- 如何记录观察和失败。

先做一个最小可行版本，再根据遇到的问题补课。每次只改动一个主要因素，并保存修改前后的结果；这样更容易区分是概念理解、实现错误、数据质量还是工具配置导致了变化。失败的尝试也要留下触发条件、观察到的现象和下一步假设，避免仅凭印象重复试错。

项目结果不能自动证明通用规律。样本少、输入单一或环境特殊时，只能说明在这些条件下观察到了什么；把结论推广到其他输入前，需要新的检查。

## 每周复盘模板

下面的清单可复制到笔记中。每项回答一两句话即可。

```markdown
- 本周要完成的可检查结果：
- 使用的前置知识：
- 小练习和输入：
- 预期结果：
- 实际结果：
- 与预期不符的地方：
- 下一步只改变的一个因素：
- 需要查阅的概念或文档：
- 目前结论适用的条件：
```

复盘时先记录事实，再提出解释。将“运行成功”与“结果正确”分开；运行成功说明流程完成了某一步，正确性仍要通过独立样例、边界输入或测量证据来判断。遇到卡点时，缩小问题到一个输入、一个步骤或一个假设，再找对应资料，不必一次重学全部内容。
