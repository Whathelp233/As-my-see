# C++ 值类别、句柄与资源所有权

C++ 的引用、值类别与资源所有权是三个相关但不同的问题。引用说明一个表达式如何指向对象；值类别影响重载解析与是否可被移动；所有权说明谁负责资源的释放。把它们分开理解，可以避免误读 `std::move`、悬空引用和系统句柄。

## 左值、右值引用与表达式类别

值类别描述的是**表达式**，不是变量本身，也不单由声明类型决定：

- **左值（lvalue）**通常指有身份、可通过名称持续访问的对象表达式，例如命名变量 `value`。
- **将亡值（xvalue）**指仍有身份、但可将资源交给其他对象的表达式，常见于显式右值转换 `std::move(value)`。
- **纯右值（prvalue）**主要用于产生值或临时结果，例如整数字面量 `42`。

右值引用变量可以绑定右值：

```cpp
std::string&& reference = std::string("example");
```

但只要表达式是一个有名字的变量，它本身就是左值。因此 `reference` 是左值表达式；需要把它再次作为可移动对象传递时，才显式写 `std::move(reference)`。这是有意的规则：仅仅给右值引用参数起一个名字不会自动消耗它。

### std::move 不执行移动

`std::move(x)` 本质上是把表达式转换成适当的右值引用类别。它本身不分配、不释放、不搬运任何成员；之后被调用的构造函数或赋值运算符才可能执行移动。移动也可能退化为复制，例如类型没有移动操作、参数是 const，或实际重载选择了复制。

`std::move` 转换本身不改变对象。若之后实际调用了标准库类型的移动操作，除非该类型另有说明，源对象通常仍有效但状态未指定；这项保证不能无条件推广到自定义类型，应按其移动构造/赋值契约判断。不要假设字符串一定为空、容器一定释放容量；移动后的对象可以销毁或重新赋值，读取其具体值前应先恢复到自己能理解的状态。

以下是**语义片段**，只展示引用绑定和移动构造调用分别发生的时机：

```cpp
std::string source = "data";
std::string&& alias = std::move(source);  // 只绑定引用，没有移动构造
std::string destination = std::move(alias);  // 此处才调用相应构造函数
```

**完美转发与移动不同。** 在模板转发函数中，`std::forward<T>(value)` 根据模板推导保留调用方传入的左值/右值类别；`std::move(value)` 则无条件把表达式按可移动对象处理。泛型包装函数通常应使用 `std::forward`，而不是无条件 `std::move`。

## 生命周期、引用与悬空对象

引用不会拥有被引用对象。返回局部变量的引用会在函数返回后悬空；保存异步回调中的引用或裸 `this` 也可能在对象销毁后访问失效内存。某些直接绑定临时对象的引用声明会延长临时对象寿命，但这种延长有明确的语法和上下文边界，不能通过把引用再传一层就自动延长。接口若要跨越异步任务或容器保存，应保存值，或使用所有权明确的智能指针/生命周期对象。

## 资源所有权与 RAII

文件描述符、套接字、文件映射、锁和线程等资源需要成对管理。RAII 把资源释放绑定到对象析构：

- 单一所有者优先使用 `std::unique_ptr` 或自定义不可复制的资源包装类。
- 只有多个对象确实需要共同延长生命周期时才使用 `std::shared_ptr`；共享所有权不等于线程安全。
- 指向外部对象的裸指针、引用或 `std::span` 可作非拥有型观察接口，但必须说明对象在何时仍然有效。
- 资源包装类要正确处理移动：移动后源对象不再拥有资源；析构不能重复释放。
- 若资源句柄数值可复用，不能把“句柄数值相同”当成“还是原对象”。

一个操作系统“句柄”是接口提供的引用标识，不是普遍固定的内存地址。POSIX fd 通常是进程内的整数索引；Windows 等接口也可能使用整数或不透明指针型值。句柄关联什么对象、允许哪些操作、何时失效，由具体 API 决定。fd 可以通过 `read`/`write` 改变文件或设备状态，访问模式受打开标志、权限和对象语义约束；因此不能笼统说句柄总是只读或不能修改。

## 回调、bind 与函数签名

`std::bind`、`boost::bind` 和 lambda 都可以形成可调用对象，但必须和接收者需要的函数签名匹配：参数个数、参数顺序、占位符、const 限定与返回类型都可能影响重载。模板错误常常会展开成很长的诊断，因此先读最内层的“无法将某可调用对象转换成某类型”或“参数不匹配”，再对照目标 typedef/函数声明。

现代 C++ 中，短 lambda 往往比 `bind` 更直接：

```cpp
auto callback = [this](int code) {
    handleResult(code);
};
```

若回调会在当前对象寿命之外被调用，捕获 `this` 仍不安全；应采用明确的对象所有权、弱引用检查、取消机制，或在析构前停止并等待回调。长任务的线程、Future、取消和析构顺序见[软件模块与异步任务](../ROS与软件架构/软件模块与异步任务.md)。

## 容器与宏的选择

`std::unordered_map` 使用哈希组织键值，不承诺按键排序；查找平均复杂度通常接近常数时间，但最坏情况会随冲突增长。若迭代顺序需要稳定，选择有序容器或显式排序。预计元素数量已知时可用 `reserve` 减少重散列；不能依赖某次运行中的哈希遍历顺序生成持久文件或网络协议。

要把 `std::vector` 的已有元素设为某个值，可用 `std::fill`；要用给定个数和值替换其内容，可用 `assign`。`memset` 是逐字节写入，不是通用的“把 C++ 对象设为零”：对拥有非平凡不变量的对象使用它可能破坏对象状态。即使对整数数组，字节全零是否对应所需数值也应按类型表示与目标语义判断；首选类型安全的算法或构造方式。

C/C++ 宏是在预处理阶段替换记号，不是类型安全的函数。例如 `#define ADD(a, b) a + b` 缺少括号，例如 `2 * ADD(1, 2)` 会展开为 `2 * 1 + 2`，与期望的 `2 * (1 + 2)` 不同；而 `#define MAX(a, b) ((a) > (b) ? (a) : (b))` 会重复求值胜出的参数，传入带副作用的表达式可能重复执行。普通常量、短函数和泛型逻辑优先使用 `constexpr`、`inline` 函数或模板；宏更适合条件编译、少量声明生成等预处理需求。

`std::string::find`、`compare` 和 `substr` 可以查子串、比较或取子串，但不是模糊相似度算法。若要“找最接近的候选”，先定义匹配规则、归一化、距离度量（如编辑距离）与阈值，再选择适合的库；正则表达式用于模式匹配，也不会自动给候选打相似度分数。

## 线程的基本边界

线程允许同一进程内的执行流并发运行；多个线程可访问共享地址空间，所以共享可变状态必须满足 C++ 内存模型。互斥锁、原子操作、线程安全容器或消息传递用于建立同步关系。多进程有各自的地址空间，通常通过管道、套接字、共享内存等显式 IPC 通信。

本节只强调所有权和数据竞争的前提；单消费者队列、调度策略、Future、队列容量、日志背压与有序退出的主讲在[软件模块与异步任务](../ROS与软件架构/软件模块与异步任务.md)。
