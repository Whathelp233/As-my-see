# 串行协议与有界解析

串行接口只把字节按顺序送达；应用层的记录边界、字段含义和错误处理都由协议定义。一次 `read()` 可以拿到半个帧、一个帧或多个帧的一部分。驱动应先把任意分块拼成完整记录，再验证和解码。

## 设计和解析一条协议帧

常见帧格式包含同步头、版本或类型、序号、载荷长度、载荷和校验字段。解析状态机可以概括为：

1. 在字节缓冲区里找同步头；没有找到时，只保留可能成为下次同步头前缀的尾部字节。
2. 数据不够一个完整头时等待；读取长度前必须先确认最小头长度已经到达。
3. 检查版本、类型和长度边界；长度超过协议上限就丢弃候选头的一字节并重新搜索。
4. 只有缓冲区中已有完整帧时，才检查尾部、序号和校验。
5. 校验通过后再解码字段；失败时从候选同步头之后继续搜索，避免一个坏长度让解析器永久失步。

长度校验必须在切片、结构体转换或数组索引之前完成。总帧长应以受检长度计算，例如

$$
L_{frame}=L_{header}+L_{payload}+L_{trailer},\qquad
0\leq L_{payload}\leq L_{max}.
$$

接收缓冲也必须有上界。若长度字段损坏却未设最大载荷，解析器可能等待一个不可能到来的超长帧，导致内存一直增长。解析器状态应由每个设备实例持有；不要把跨设备共用的函数内 `static` 变量用于帧缓存或序号。

同步头不是绝对唯一的。若载荷允许出现相同字节，需要结合长度、版本、序号、尾部和校验共同减少误同步；转义字节、固定帧长或独立 delimiter 是协议的其他选择。序号可帮助识别丢失、重复和乱序，但它自身不能补回数据。

## 校验、字节序与有符号数

简单累加和、XOR 与 CRC 的错误检测能力不同，不能都叫 CRC。CRC 是按约定多项式对数据位计算余数。只知道“使用某个多项式”仍不足以复现结果；还需要宽度、初始值、输入/输出反射、最终异或值、覆盖字节范围、补齐规则及结果字节序。校验能发现部分传输错误，不能证明发送者身份，也不修复错误内容。

协议应逐字段规定小端或大端。不要把接收缓冲区直接 `reinterpret_cast` 成含填充的 C/C++ 结构体。先按无符号字节移位组合整数，再按协议定义解释符号位和单位；否则主机字节序、对齐和整数提升规则可能改变结果。对于 $w$ 位二进制补码值 $u$，有符号解释可写为

$$
v=\begin{cases}
u,&u<2^{w-1},\\
u-2^w,&u\geq 2^{w-1}.
\end{cases}
$$

即使长度在允许范围内，损坏的长度字段也可能让解析器一直等待后续字节。本例没有帧装配超时；真实驱动应按波特率、设备最大响应间隔等条件为残帧设置过期策略，并在过期后安全重同步。测试时至少覆盖最小/最大长度、跨多次读取的半帧、多个帧粘连、坏校验、坏长度、同步头重叠、未知版本、重复序号和断流后恢复。将解析成功和数值有效分开：字段能解码不代表测量可信，超范围的状态码也不能静默替换成数值 0。

## 从波特率估算串口时延

异步串口常以起始位、数据位、可选校验位和停止位发送每个字符。8N1 每字节约占 10 个串行位，因此理想线速预算为

$$
R_{byte}\approx\frac{baudrate}{10},\qquad
T_{wire}\approx\frac{10N}{baudrate}.
$$

该估算不包括 USB 批处理、模块处理、RS-485 方向切换、操作系统调度和协议等待。轮询周期短于一条请求与响应所需时间，不会让设备更快地产生测量。

POSIX 串口在 canonical 模式下以换行为单位提供数据；非 canonical 模式由 `VMIN`、`VTIME` 等条件决定 `read()` 何时完成。即使配置了非阻塞文件描述符或超时，返回长度仍不等于协议帧长度。[termios 手册](https://man7.org/linux/man-pages/man3/termios.3.html)

RS-485 半双工事务还需要协调驱动使能、发送完成、收发方向切换和响应读取。`tcdrain()` 等待本地输出已发送，清空输入缓存则是另一项操作。方向脚的有效电平、收发器是否自动切换和所需延迟取决于电路，不应从串口软件参数猜测。

## 串口事务与断链恢复

如果同一个串口既接收主动上报又处理请求/响应，读、写各自加锁也不一定能保护整个“清旧数据 → 发命令 → 等响应 → 验证响应”的事务。多个请求线程可能互相取走响应。应由单一事务协调者串行化命令，或通过序号和可验证的关联字段匹配响应。

断链恢复可使用显式状态机，例如 `Disconnected → Opening → Synchronizing → Running → Backoff`。重连时关闭旧文件描述符、清理不完整帧状态、重新验证设备身份和协议版本，并以有上限的退避策略重试。没有新数据、设备超时、CRC 错误和合法的零值是不同状态；下游应能区分“最近值过期”和“传感器报告零”。

## 可运行的分帧示例

下面构造一个教学用协议：2 字节同步头、1 字节序号、2 字节小端长度、最多 64 字节载荷和 2 字节校验。校验使用 CRC-16/CCITT-FALSE 参数，覆盖序号、长度与载荷，结果以小端写入；这些参数只是本例协议约定，不代表任一设备。每次 `feed` 最多接收 256 字节，解析器缓存的残帧不会超过一帧上限。

此程序只演示有界分帧、长度检查、坏帧重同步和常见边界条件，不负责串口打开、重连、线程和真实硬件时序。

```python
from dataclasses import dataclass


SOF = b"\xA5\x5A"
MAX_PAYLOAD = 64
MAX_READ = 256
MAX_FRAME = len(SOF) + 1 + 2 + MAX_PAYLOAD + 2


@dataclass(frozen=True)
class Frame:
    sequence: int
    payload: bytes


def crc16_ccitt_false(data: bytes) -> int:
    crc = 0xFFFF
    for byte in data:
        crc ^= byte << 8
        for _ in range(8):
            if crc & 0x8000:
                crc = ((crc << 1) ^ 0x1021) & 0xFFFF
            else:
                crc = (crc << 1) & 0xFFFF
    return crc


def encode_frame(sequence: int, payload: bytes) -> bytes:
    if not 0 <= sequence <= 0xFF:
        raise ValueError("sequence must fit in one byte")
    if len(payload) > MAX_PAYLOAD:
        raise ValueError("payload is too long")
    body = bytes((sequence,)) + len(payload).to_bytes(2, "little") + payload
    checksum = crc16_ccitt_false(body).to_bytes(2, "little")
    return SOF + body + checksum


class FrameDecoder:
    def __init__(self) -> None:
        self._buffer = bytearray()
        self.crc_errors = 0
        self.length_errors = 0

    def feed(self, chunk: bytes) -> list[Frame]:
        if len(chunk) > MAX_READ:
            raise ValueError("read chunk exceeds the configured bound")
        self._buffer.extend(chunk)
        frames: list[Frame] = []

        while True:
            start = self._buffer.find(SOF)
            if start < 0:
                tail = self._buffer[-1:] if self._buffer.endswith(SOF[:1]) else b""
                self._buffer[:] = tail
                break
            if start:
                del self._buffer[:start]
            if len(self._buffer) < len(SOF) + 3:
                break

            payload_len = int.from_bytes(self._buffer[3:5], "little")
            if payload_len > MAX_PAYLOAD:
                self.length_errors += 1
                del self._buffer[0]
                continue

            total_len = len(SOF) + 1 + 2 + payload_len + 2
            if len(self._buffer) < total_len:
                break

            body_end = 5 + payload_len
            body = bytes(self._buffer[2:body_end])
            received_crc = int.from_bytes(self._buffer[body_end:total_len], "little")
            if crc16_ccitt_false(body) != received_crc:
                self.crc_errors += 1
                del self._buffer[0]
                continue

            sequence = self._buffer[2]
            payload = bytes(self._buffer[5:body_end])
            frames.append(Frame(sequence, payload))
            del self._buffer[:total_len]

        return frames


def self_check() -> None:
    assert crc16_ccitt_false(b"123456789") == 0x29B1
    first = encode_frame(3, b"range")
    decoder = FrameDecoder()
    split = len(first) // 2
    assert decoder.feed(first[:split]) == []
    assert decoder.feed(first[split:]) == [Frame(3, b"range")]

    second = encode_frame(4, b"imu")
    assert decoder.feed(first + second) == [Frame(3, b"range"), Frame(4, b"imu")]

    damaged = bytearray(encode_frame(5, b"broken"))
    damaged[5] ^= 1
    assert decoder.feed(bytes(damaged) + second) == [Frame(4, b"imu")]
    assert decoder.crc_errors == 1

    invalid_length = SOF + bytes((9,)) + (MAX_PAYLOAD + 1).to_bytes(2, "little")
    assert decoder.feed(invalid_length + second) == [Frame(4, b"imu")]
    assert decoder.length_errors == 1

    try:
        decoder.feed(bytes(MAX_READ + 1))
    except ValueError:
        pass
    else:
        raise AssertionError("oversized input chunk was not rejected")

    assert len(decoder._buffer) <= MAX_FRAME
    print("self-check passed: split, concatenated, CRC, length, and input bounds")


if __name__ == "__main__":
    self_check()
```
