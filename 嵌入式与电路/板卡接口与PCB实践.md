# 板卡接口与 PCB 实践

## MCU 与单板计算机的接口边界

MCU 与单板计算机（SBC）承担不同层次的工作：SBC 运行操作系统、网络和较复杂的应用；MCU 靠近传感器与执行器，负责确定时序的采样、输出和快速故障保护。主机经 UART、USB 或以太网发送命令，设备端应有明确的报文格式、超时和失联安全状态。即使上层通过 ROS 通信，GPIO、PWM 与串口仍遵守各自的硬件电气规格。

接口连接前先确认：

1. **信号电平**：双方的高低电平阈值与绝对最大额定值是否兼容；3.3 V、5 V 和 RS-232 不能仅因都叫“串口/GPIO”就直接互连。
2. **电流能力**：I/O 引脚通常只适合逻辑信号，电机、灯带和继电器等负载需要驱动级；检查连续/峰值电流、功耗、感性负载回扫和保护电路。
3. **参考地与隔离**：未隔离的信号通常需要共同参考地；若地电位差、噪声或安全要求不允许共地，应选择合适隔离器和电源方案。
4. **供电顺序与回灌**：不得假设 I/O 在未上电时仍可承受外部高电平；检查掉电状态、钳位二极管和数据手册的注入电流限制。
5. **连接器与针脚**：按板卡原理图、丝印和对应芯片封装核对方向、管脚复用和电源脚，不只依据网上的通用排针图。

## GPIO 编号、复用与 Linux

同一个板卡的 GPIO 可能同时有芯片引脚名、SoC GPIO offset、连接器物理脚号、厂商库编号等多套标识。板卡版本、设备树、内核驱动和复用配置会改变可用性。查引脚时应把“连接器位置 → SoC 管脚 → 当前 pinmux 功能 → Linux GPIO chip/line”逐层映射，先确认引脚是否被 UART、SPI、I²C、PWM 或其他驱动占用。

旧资料常用 `/sys/class/gpio` 的导出接口控制用户态 GPIO。该接口已属历史 ABI；现代 Linux 提供 GPIO character device API，由用户态通过 `/dev/gpiochipX` 请求某个 GPIO line。实际 GPIO 访问仍应优先考虑现有内核子系统驱动（如 I²C、SPI、PWM）是否已经提供适当接口，避免绕过驱动直接翻转引脚。权限和 line 编号依赖系统配置，不能把某台机器上的编号或 root 操作流程写成普遍规则。

用主机 GPIO 控制外围器件时，按“枚举设备、确认驱动与占用、申请 line、设置方向/偏置、读写或监视边沿、释放资源”的顺序排查。看不到设备节点可能是硬件枚举、驱动、设备树、pinmux、权限或内核接口版本不同；先查系统枚举与内核日志，避免直接改全局配置脚本。

## UART 转换与线缆

MCU UART 引脚常为 CMOS/TTL 逻辑电平。RS-232 收发器负责将 UART 逻辑信号转换为具有不同电压范围和极性的 RS-232 物理信号；USB-UART 转换器则把 USB 与 UART 逻辑电平相连。使用前检查 TX/RX 交叉、公共地、收发器供电、电平选择和连接器定义。超过板级连线能力的距离或较强共模干扰场景，应评估差分物理层与隔离方案，而不是提高 UART 逻辑电压。

## 电源与回流路径

电源设计要同时满足稳态电流、启动/堵转峰值、纹波、瞬态和热约束。高边沿电流回路应尽量缩小面积，去耦电容靠近供电引脚并缩短回路；逻辑电源与电机等噪声负载应根据电流路径和地回流规划，避免大电流在敏感模拟参考地上形成压降。电源入口、保护器件、稳压器、负载和连接器应按故障电流、发热和维护要求布局。

## PCB 走线与载流能力

铜箔走线的直流电阻可用均匀矩形导体近似：

$$
R\approx\rho\frac{L}{w t},\qquad P_{loss}=I^2R
$$

其中 $L$ 为长度、$w$ 为线宽、$t$ 为铜厚、$\rho$ 为电阻率。这个模型可用于估算压降和铜损，但不能单独推出“某线宽必然可通过多少安培”：温升还依赖内外层、铜平面、板材、环境温度、气流、邻近走线和允许温升。高频下还要考虑趋肤效应、回流路径、特征阻抗和串扰。

PCB 铜厚常以 oz/ft² 标注；换算为厚度时应按制造商提供的成品铜厚数据，而不是把“盎司”直接当作线宽或电流单位。选线宽、过孔数量和铜厚时，使用符合项目条件的 IPC-2152 计算资料或可信的制造商工具，并把阻抗、温升和压降分别校核；关键电源路径还应测量满载温升与电压降。任何经验表都要连同其铜厚、层数、外/内层、环境和温升条件阅读。

模拟输入与高速数字信号应尽量保持连续回流平面，避免跨越地平面分割。开关节点和大电流回路需与高阻模拟输入、时钟和复位线保持适当距离。连接器附近留出保护与测量位置，便于调试和验证。
