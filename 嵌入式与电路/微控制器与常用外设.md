# 微控制器与常用外设

微控制器（MCU）把处理器、存储器和定时器、GPIO、串行接口等外设集成在一颗芯片上。它适合执行时限明确、资源受限的控制任务。单板计算机（SBC）则通常运行完整操作系统，适合运行 ROS 等较复杂的软件；需要确定性时序的采样和输出，通常仍交给 MCU 或专用外设完成。

## GPIO 与电气边界

GPIO 可由软件配置为输入或输出，通常还支持上拉/下拉、推挽/开漏、中断和复用外设等模式。

- **输入**读取引脚逻辑状态；引脚悬空时电平可能不确定，需要外部或内部偏置。
- **推挽输出**主动拉高和拉低，不能与另一推挽输出直接相连。
- **开漏/开集输出**只能主动拉低，逻辑高由上拉电阻产生，常用于共享线路；上拉电压和电流必须同时符合所有器件规格。
- **复用功能**把引脚接到定时器、UART、SPI 等外设。一个物理引脚通常不能同时执行互相冲突的复用功能。

Arduino API 片段（调用示例，不含板卡入口和引脚定义）：

```cpp
pinMode(pin, OUTPUT);
digitalWrite(pin, HIGH);
```

`pin` 的编号和该板的逻辑高电平电压由目标板卡决定。此接口片段只展示配置方向与写逻辑状态，不代表任何板卡都输出 5 V。

`HIGH` 和 `LOW` 是逻辑状态，不表示跨板卡恒定的 5 V 和 0 V。高电平范围、输入阈值、耐压和单引脚/整组引脚电流均由具体芯片数据手册规定。两设备连接前应先确认逻辑电压兼容、信号地参考一致，以及是否需要电平转换或隔离。

## 定时器、周期与 PWM

通用定时器由时钟、预分频器、计数器和比较寄存器组成。比较匹配时可翻转或置位输出引脚，形成周期波形。对**边沿对齐、向上计数**的常见配置，若定时器时钟为 $f_{timer}$、预分频寄存器为 $PSC$、自动重装值为 $ARR$，则

$$
f_{PWM}=\frac{f_{timer}}{(PSC+1)(ARR+1)},\qquad
D\approx\frac{CCR}{ARR+1}.
$$

这里 $CCR$ 是通道比较值，$D$ 是高电平占空比。实际公式还取决于计数方向、PWM 模式、重装/比较值边界和具体定时器配置；中心对齐模式、互补输出和死区设置会改变关系。多个通道若共享同一个计数器和自动重装值，通常共享周期、分别设置比较值；若需要不同周期，应核对目标芯片的定时器资源并考虑使用不同定时器。

STM32F4 HAL 片段（依赖已配置的定时器句柄、时钟树和 GPIO 复用，不是独立程序）：

```c
if (HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1) != HAL_OK) {
    /* 记录并处理启动失败 */
}
__HAL_TIM_SET_COMPARE(&htim3, TIM_CHANNEL_1, compare_ticks);
```

该 STM32F4 HAL 宏名区分大小写，正确写法是 `__HAL_TIM_SET_COMPARE`（`SET` 全大写）。先配置好计数器周期、PWM 模式、通道和引脚复用，再更新比较值；运行期间修改比较寄存器是否在周期边界生效，取决于该定时器的预装载配置。

PWM 不是普通“模拟电压”输出。它以数字高低电平的占空比控制平均能量；负载需要真正的模拟电压时，应使用 DAC 或经滤波的 PWM。伺服、电机驱动等外设对周期、脉宽、电流和保护有各自要求，须查对应规格，不要把常见脉宽范围当作所有设备的统一值。

## UART：字节流与帧格式

UART 常用 TX、RX 和参考地连接两端，按约定波特率异步收发。每个字符帧包括起始位、数据位、可选校验位和停止位。两端需要匹配波特率、数据位、校验和停止位。UART 逻辑信号通常是芯片引脚电平；RS-232 等物理层的电压范围和极性不同，不能直接接到 MCU UART 引脚，应使用相应收发器。USB 转 UART 也需要确认收发器一侧的逻辑电压与板卡一致。

UART 是字节流，没有天然的消息边界。上层协议应明确帧头/长度/校验/超时或转义规则，接收代码必须处理拆包、粘包、丢字节与缓冲区溢出。相关物理层和传感器协议的主讲见[传感器与硬件通信](../传感器与硬件通信/串行协议与有界解析.md)。

## I²C 与外设访问

I²C 通常使用时钟线 SCL 和数据线 SDA；总线由上拉电阻将开漏信号拉高，器件以地址和读写时序参与通信。上拉阻值、总线电容、线长、速率和器件输入阈值彼此相关。连接前核对器件供电与上拉电压，不能把 5 V 上拉接到不耐 5 V 的引脚。I²C 的寄存器地址、总线事务和传感器数据格式应以器件数据手册为准。

STM32F4 HAL 的内存读 API 片段（对应本文参考的 STM32F4 HAL 版本；句柄、寄存器地址与错误处理由调用工程提供）：

```c
uint16_t dev_addr = (uint16_t)(addr_7bit << 1);
uint8_t rx[2];
HAL_StatusTypeDef status = HAL_I2C_Mem_Read(
    &hi2c1, dev_addr, reg_addr, I2C_MEMADD_SIZE_8BIT,
    rx, 2, timeout_ms);
if (status != HAL_OK) {
    /* 记录错误；按系统策略重试或进入故障状态 */
}
```

该 HAL 版本的 `DevAddress` 参数要求把数据手册中的 7 位从机地址左移一位；不要把读写位手工并入地址，HAL 会根据读/写方向形成线上地址字节。`HAL_I2C_Mem_Read` 返回 `HAL_StatusTypeDef`，缓冲区长度和超时要按事务需要设定，并检查返回值。

SPI 使用时钟、数据和片选等信号，通常由主机管理片选。时钟极性、采样相位、位序、片选时序和允许的时钟频率需要与从设备匹配。总线种类相同不代表寄存器协议相同。

## 中断、缓冲区与 DMA

中断适合响应需要及时处理的事件，例如定时器更新或接收数据。中断服务程序应短小、可预测：读取状态、保存必要数据、清除标志并尽快退出；耗时计算、阻塞等待、动态内存操作和复杂日志通常放到主循环或任务线程。若主程序和中断共享数据，应考虑原子访问、临界区和编译器可见性；`volatile` 只约束部分优化行为，本身不保证复合读写的原子性。

在 STM32 HAL 中，UART 接收中断的典型调用链是：设备 IRQ 入口调用 `HAL_UART_IRQHandler`，接收达到 `HAL_UART_Receive_IT` 请求的字节数后，HAL 调用 `HAL_UART_RxCpltCallback`。回调在中断上下文运行；它应快速复制/入队数据，并在仍需连续接收时重新启动接收，同时检查 HAL 返回状态。回调拿到的缓冲区会被下一次接收复用，需明确缓冲区所有权和并发访问规则。若只接收一字节/次，逐字节中断也会带来较高开销，可按吞吐率评估环形缓冲或 DMA。

高吞吐串口可由 DMA 在外设与内存缓冲区之间搬运数据，减少每字节中断开销。DMA 仍需软件处理缓冲区边界、环形计数、缓存一致性（若有数据缓存）、错误标志及生产者/消费者同步。中断/DMA 均不能替代协议层的长度、校验和超时处理。

## 定时器编码器接口

许多 MCU 定时器可接收正交编码器的 A/B 两相信号并累计边沿，方向由相位先后关系决定。初始化时须核对输入滤波、计数模式、计数器宽度、溢出处理和机械/电气计数定义。编码器的分辨率、计数方向和速度估计见[编码器：计数、方向与参考位置](../传感器与硬件通信/传感器测量与时间戳.md#编码器计数方向与参考位置)的主讲范围；本节只说明它是定时器的硬件输入模式。

## 开发工具与代码生成

STM32CubeMX 一类配置工具可以根据具体 MCU 和引脚配置生成初始化框架，但不会替代对时钟树、复用冲突、中断优先级、DMA 缓冲区和外设时序的理解。代码生成器版本、芯片封装和 HAL 版本都会影响可用选项与函数接口。移植时应阅读目标系列的参考手册、数据手册及生成代码注释，并检查时钟配置与实际板卡晶振是否一致。

Arduino 提供统一的 `pinMode`、`digitalRead`、`digitalWrite`、`analogRead` 和 `analogWrite` 风格接口，但接口名称统一不等于各板卡的电压、分辨率、引脚能力或实现机制一致。以 ESP8266 Arduino Core 为例，中断处理对执行区、延时调用和处理时间有平台限制；部分 PWM 实现也与具体核心版本有关。中断处理函数、模拟输入范围、PWM 范围和串口映射均应按目标板卡和核心版本确认。

## ROS 主机与微控制器

ROS 主机与 MCU 之间可以通过串口、USB 或网络桥接。分工上，主机处理高层消息和非实时逻辑，MCU 执行引脚采样、PWM 更新、限位保护和低层状态机；双方需要约定单位、坐标/方向、超时、序号、校验和故障状态。

`rosserial` 是面向 ROS 1 的串行桥接方案之一：MCU 侧运行受限的客户端库，主机运行桥接节点。MCU 并不因此变成运行完整 ROS master 的主机。ROS 2 有不同的通信和中间件机制，不能把 ROS 1 的命令、包和 API 直接照搬；节点与接口契约见[ROS 与软件架构](../ROS与软件架构/节点执行与组件化架构.md)。
